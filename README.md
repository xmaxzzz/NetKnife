# NetKnife

Личный сетевой «швейцарский нож» для Windows 11 — одно окно на PowerShell 7 + WPF, без установки.

- **SSH**: хосты из `~/.ssh/config`, ключи, проверка доступности, установка ключа по паролю, сниппеты, scp drag-and-drop, туннели `-L/-D/-R`.
- **Сеть**: сканер диапазонов (ping + порты + MAC/вендор + имена), карта маршрута до нелокальной сети, порты/nmap, пинг и трассировка, DNS, сканер Wi-Fi (соседние точки), монитор хостов, тест скорости, калькулятор подсетей.
- **VPN**: профили `vless://`, `hysteria2://` (как в Happ), `mierus://` (ссылка `mieru export`) и `naive+https://` / `naive+quic://`. VLESS идёт через xray-core, Hysteria2 и mieru через mihomo, NaïveProxy через официальный `naive.exe` за mihomo (naive слушает SOCKS на внутреннем порту, логин и пароль только в `naive.json`, который удаляется после старта). Движки скачиваются по закреплённому тегу официального GitHub-релиза, SHA256 архива сверяется с записанным в NetKnife, при несовпадении файл удаляется. Дальше — системный прокси, проверка выхода, пинг и трафик, переключение из трея.
- **Терминал** прямо в окне (ConEmu `-InsideWnd`, скачивается сам).
- **Wi-Fi обход для Helpdesk** — см. ниже.
- Трей, глобальный хоткей `Ctrl+Alt+N`, автообновление с GitHub Releases.

## Wi-Fi обход (сборщик для Helpdesk)

NetKnife на вкладке «Wi-Fi обход» только **собирает** обход и отправляет его в Helpdesk
([help.butlerdc.ae](https://help.butlerdc.ae)). Распознавание голоса, хронология помещений, трек, роуминг, расчёт
мощностей и каналов, сравнение «до/после», отчёт и мастер «Настройка сети Omada» — в вебе Helpdesk
(«Объект → Инструменты → Wi-Fi»). Протокол — `netknife-survey/1`, контракт: `docs/WIFI-COLLECTOR-NETKNIFE.md` в
репозитории helpdesk.

1. **Подключить.** В Helpdesk: «Объект → Инструменты → Wi-Fi обследование → Подключить NetKnife» → «Скопировать».
   В NetKnife: «Подключить к Helpdesk» → вставить строку (или голый код из 43 символов) → «Подключить». Код
   одноразовый, 15 минут. Токен привязан к объекту и хранится в `settings.json` зашифрованным (DPAPI текущего
   пользователя Windows). Можно подключить несколько объектов; «Проверить» показывает объект, пользователя, `…last4`,
   распознаётся ли голос на сервере и лимиты; «Отключить» удаляет токен из NetKnife (отозвать — в вебе).
2. **Выбрать** объект → план → серию («до», «после» или своя). Справочник кэшируется в
   `%APPDATA%\NetKnife\collector\` и работает без сети. Объект без права записи — «Старт» недоступен.
3. **Обход.** «Старт» — микрофон, монитор подключения и скан эфира. Назови помещение вслух, кликни на плане, где
   стоишь, или выбери «Я в: …»; «Дошёл до N» / пробел — по маршруту плана; «Отметка» — «тут плохо». Обход
   сохраняется каждые 30 с (`*.json.partial`); если программа закрылась на ходу, при следующем запуске она предложит
   отправить незавершённый обход.
4. **«Стоп и отправить»** ставит обход в очередь `%APPDATA%\NetKnife\outbox\<объект>\<id>\` (`envelope.json`,
   `walk.wav`, `state.json`). Отправка идёт в фоне: конверт в gzip, запись частями по 8 МиБ с докачкой, повторы с
   паузой 10 с · 2ⁿ (не больше 15 мин), при смене сети и по кнопке «Отправить сейчас». В списке очереди — стадии
   сервера («распознаём голос», «строим хронологию», «готов · помещений N») и «Открыть в Helpdesk». Отправленное
   хранится 14 дней, ошибки — пока не уберёшь сам. На 401 (токен отозван) и 409 (на сервере другой обход с этим Id)
   обход не повторяется: каталог получает суффикс `-r2`, в строке — «Отправить снова» / «Отправить как новый» /
   «Убрать из очереди».
5. **Старое.** Меню «…»: «Отправить старые планы в Helpdesk» (`wifiplan\<объект>.json` + картинка → новый план
   объекта) и «Отправить старую прогулку в Helpdesk» (`wifiplan\*.walk-*.json`, без локального разбора). Файлы
   в `wifiplan\` не удаляются.

Кнопки «Монитор» и «Эфир» на той же вкладке — монитор подключения (точка, RSSI, канал, шлюз/интернет/DNS, события
роуминга) и сканер Wi-Fi.

## Тесты

```
pwsh -c "Invoke-Pester -Path tests"
```
Pester 5. `tests/Collector.Tests.ps1` — клиент протокола против сервера в памяти; `tests/App.Tests.ps1` — целостность
(удалённые модули, разбор скриптов, имена элементов `Main.xaml`). Работают и в pwsh на Linux (DPAPI — только Windows).

## Запуск

```
pwsh -STA -File NetKnife.ps1
```
или `launch.vbs` (без консоли). Нужен PowerShell 7. Движки (xray, mihomo, ConEmu) скачиваются с их официальных GitHub-релизов в `%APPDATA%\NetKnife\`.

## Выпуск релиза

```
git switch main; git pull --ff-only
pwsh -File tools\Publish.ps1 -Bump -DryRun                  # проверки + сборка zip, ничего не коммитит и не отправляет
pwsh -File tools\Publish.ps1 -Bump -Notes "что нового"      # или -Version X.Y.Z.N вместо -Bump
```

Скрипт сначала проверяет и **ничего не меняет**, если что-то не так (ошибка по-русски — что именно и что сделать):

- `gh auth status` в порядке;
- после `git fetch origin`: текущая ветка `main`, рабочее дерево чистое (`git status --porcelain`, неотслеживаемые
  файлы тоже считаются, игнорируемые нет), `HEAD` == `origin/main` — не впереди и не позади;
- тега новой версии нет ни локально, ни на origin, и релиза с таким тегом на GitHub нет.

Дальше: `VERSION` → `NetKnife.zip` во временной папке → коммит `release vX` только с `VERSION` (без `git add -A`) →
тег → `git push --atomic origin main vX` (main и тег уходят вместе или никак; при обрыве связи тот же атомарный push
повторяется до 3 раз) → `gh release create` только после успешного push.

- Push не прошёл — релиз не создаётся, локально тег удаляется и `main` сбрасывается на исходный коммит (дерево было
  чистым, терять нечего).
- Push прошёл, а релиз не создался — скрипт пишет, что коммит и тег уже на GitHub, и печатает готовую команду
  `gh release create …` для ручного завершения.

`-DryRun` делает все проверки и собирает zip, затем возвращает `VERSION`; коммита, тега, push и релиза нет.
Тесты скрипта (git/gh замоканы): `Invoke-Pester tests\Publish.Tests.ps1`.
